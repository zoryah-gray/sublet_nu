# Backend conventions

Applies to `apps/backend/`. SQL rules live in `.claude/docs/sql.md`, migration rules in `.claude/docs/migrations.md`.

## File names

| Kind | Delimiter | Example | Why |
|---|---|---|---|
| Python (`functions/**`) | `_` (snake_case) | `post_confirmation.py` | Python can't `import` a hyphenated module name. Matches PEP 8 |
| TypeScript CDK (`lib/`, `bin/`) | `-` (kebab-case) | `auth-stack.ts` | Existing CDK/Next.js convention in this repo |
| Migrations | node-pg-migrate timestamp + `-` | `1793519637032_users-auth-identity.mjs` | Generated by `npm run migrate:create` |
| SQL / shell scripts (`db/`) | `-` (kebab-case) | `queries-realistic.sql`, `run-sql.sh` | Majority case in `db/` |

Lambda layout: one folder per domain under `functions/` (`auth/`, `match/`, `messaging/`, `notifications/`, `search/`). Each folder has its own `requirements.txt`. Shared code lives in the layer at `functions/layer/python/` and is imported as a top-level module (`from utils import ...`). Never copy it into a function folder.

Lambda handler files are named after their Cognito trigger (`pre_sign_up.py`, `post_confirmation.py`).

### CDK construct IDs

PascalCase, describing the resource, with no project prefix (the stack already scopes it): `Vpc`, `Database`, `UserPool`, `HostedDomain`, `WebClient`, `AuthDomainFn`, `ProvisionUserFn`. TypeScript variables stay camelCase. Renaming an ID after deploy **replaces** the resource. `BackendStack` keeps its deployed ID.

### Left as-is (decided)

- `apps/frontend/app/components/login_signup/` and `apps/frontend/public/stock_images/` keep `_`.
- `__tests__/` is a tooling convention.

## Python functions

- Type hints on every parameter and return: `def derive_base_display_name(email: str) -> str:`. Use built-ins (`dict`, `str | None`). No `typing` import is needed on Python 3.12.
- One docstring per function: what it does, its inputs, its output. Add a line only for non-obvious rules (fallbacks, fail-closed behavior, races).
- Lambda handlers are `lambda_handler(event: dict, context: object) -> dict`.
- Exceptions raised from a Cognito trigger are shown to the user. Raise a generic message, and `print` details (never emails or names) for CloudWatch.
- Never log a database driver's error message: Postgres can embed the failing row. Log the error type, `pgcode` and constraint name only.
- DB connections use `sslmode='verify-full'` with `utils.RDS_CA_BUNDLE`.

## Derived fields

**A field derived from another field is recomputed wherever it's read, never stored at write time.**

- `avatarInitials` comes from `full_name` (fallback: `display_name`) via `utils.avatar_initials`. It has no column.
- When the Settings/Edit-Profile endpoint that edits `full_name` or `display_name` is built, it writes only those columns. Initials follow automatically.
- Same rule ADR 7 applies to academic terms derived from `availability_date_range`.

## Server Actions (frontend)

**Every Server Action verifies the session itself**: first line `await requireSession()` (`apps/frontend/app/lib/dal.ts`). Server Actions aren't separate routes in Proxy's execution chain. A matcher that excludes a path also skips Proxy for any Server Action called from it, so `proxy.ts` is never the only gate. Audit: `updateContactMethod` (`app/actions/settings.ts`) is the only Server Action today; `__tests__/auth/server-action.test.ts` checks it rejects an unauthenticated call.

## Proxy matcher (frontend)

`apps/frontend/proxy.ts` skips only an explicit list of static locations. Never exclude by file extension: any dynamic route would then skip auth for `/<route>/<id>.png`. `__tests__/auth/audit-regressions.test.ts` pins this.

## Environments

`ENVIRONMENT` is `dev` or `prod`, with no default anywhere. CDK refuses to synth without it (`bin/backend.ts`), and the PreSignUp Lambda rejects every sign-up without it.
